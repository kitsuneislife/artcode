# ArtKit Quickstart

ArtKit is Artcode's reactive UI framework. Components are declared in `.art` files, compiled to vanilla JavaScript with no virtual DOM, and run directly in the browser.

## Prerequisites

- Artcode CLI installed (`art --version`)
- Node.js 18+ (for bundle verification)

## Hello World

Create `counter.art`:

```art
component Counter {
    state count: Int = 0

    view {
        <div>
            <p>{count}</p>
            <button on:click={increment}>+</button>
        </div>
    }
}

func increment() {
    set_count(count + 1)
}
```

Compile to a self-contained bundle:

```sh
art build --target js --bundle counter.art --out dist/
```

This produces `dist/counter.js` containing the Artcode runtime, the component, and all helpers.

## Using in a browser

```html
<!DOCTYPE html>
<html>
  <body>
    <div id="app"></div>
    <script src="dist/counter.js"></script>
    <script>Counter_create(document.getElementById("app"));</script>
  </body>
</html>
```

Open the file in a browser. Clicking `+` increments the counter — only the `<p>` text node is updated, no full re-render.

## Binding qualifiers

| Qualifier | Meaning |
|-----------|---------|
| `state`   | Mutable reactive value; `set_X(v)` schedules a DOM patch |
| `prop`    | Read-only value passed from the host element's attribute |
| `memo`    | Derived value recomputed when its dependencies change |
| `ref`     | DOM reference (non-reactive; use `state` for reactive values) |

## Lifecycle hooks

Register callbacks from outside the component using the JS API generated by the runtime:

```js
const comp = Counter_create(host);
on_mount(comp, () => console.log("mounted"));
on_destroy(comp, () => console.log("destroyed"));
on_update(comp, () => console.log("count changed"), ["count"]);
```

## How it works

1. `art build --bundle` runs the ReactivityPass over your component AST, building a dependency graph (state → memo → view sinks).
2. The codegen emits `set_X(v)` functions that recompute only the affected memos (topological order) and patch only the named text nodes that display those values.
3. DOM updates are batched via `queueMicrotask` so multiple `set_X` calls in a single event handler flush in one microtask.
